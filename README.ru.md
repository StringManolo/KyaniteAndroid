# KyaniteAndroid

Альтернатива Termux для опытных пользователей: [**Kyanite**](https://github.com/StringManolo/Kyanite) — небольшая Linux-система rootfs с безопасным управлением памятью, написанная на Rust, с `kpkg` и Brush, работающая на Android. Создана на основе [KotlinApkTemplate](https://github.com/StringManolo/KotlinApkTemplate) и полностью собирается с помощью GitHub Actions. Форк проекта [DebianLiveCD4Android](https://github.com/StringManolo/DebianLiveCD4Android).

🌐 **[Официальный сайт](https://stringmanolo.github.io/KyaniteAndroid/)** · Введение для пользователей, скриншоты, возможности и инструкция по загрузке.

📱 **[Скачать Kyanite для Android](https://github.com/StringManolo/KyaniteAndroid/releases/latest/download/Kyanite.apk)**

- Kyanite работает через **proot** (форк `termux/proot`), а не внутри префикса в стиле Termux.
- Rootfs Kyanite — подписанный файл `kyanite-rootfs-aarch64.tar.xz` из релизов Kyanite, включённый в APK (около 8 МБ). Перед упаковкой CI проверяет его SHA-256 и подпись Ed25519 (см. раздел Build).
- Программное обеспечение, устанавливаемое впоследствии, поступает из `kpkg` / `apt` внутри Kyanite; приложение не зависит от содержимого rootfs.
- Эмуляция терминала использует `terminal-emulator` / `terminal-view` из Termux с дополнительной панелью специальных клавиш (ESC, TAB, CTRL, ALT, HOME, END, PGUP, PGDN и стрелки; короткое нажатие модификатора активирует его один раз, долгое нажатие фиксирует его).
- `targetSdk 28` выбран намеренно: более новые значения target SDK не позволяют запускать бинарные файлы из каталога данных приложения (W^X).

## Первый запуск, окружения и режимы (кнопка ⚙ доступна всегда)

Ничего не устанавливается и не запускается, пока вы сами этого не выберете. При первом запуске открывается экран настроек.

| | **Normal** | **Ephemeral** | **VM** |
|---|---|---|---|
| **System** | proot поверх установленной Kyanite | proot поверх временной копии, удаляемой при выходе | QEMU, установленная система передаётся в оперативную память гостевой системы |
| **LiveCD** | proot поверх постоянной распакованной системы | новая распаковка при каждом запуске, удаляемая при выходе | QEMU, встроенный образ передаётся в оперативную память гостевой системы |

**Режимы никогда не используют хранилище друг друга.**

- Каждая **System** находится в `files/systems/<id>/`. Изменять её можно только в режиме System + Normal, когда она выбрана. Системы создаются, импортируются или загружаются вручную через Настройки > Systems; автоматическая установка не выполняется.
- Данные постоянного хранения **LiveCD** (`files/systems/livecd/`) изменяются только в режиме LiveCD + Normal.
- **Ephemeral** использует `files/eph/*` и удаляет эти данные при выходе (а также при следующем запуске, если приложение было принудительно завершено).
- **VM** ничего не записывает на диск. System + Ephemeral/VM только читают установленную System и отказываются запускаться, если она не установлена (никогда не устанавливают её самостоятельно).
- Единственный явно разрешённый доступ между системами: сеанс LiveCD в режиме proot может подключить установленную System в `/mnt/system` (чтение и запись, по желанию в настройках). Это похоже на LiveCD, который подключает жёсткий диск для восстановления или резервного копирования. В режиме VM это недоступно.

**Ephemeral использует диск, а не RAM**: флеш-память (F2FS, выравнивание износа) может сохранять остаточные данные.

**VM — единственный режим без следов на диске**: `qemu-system-aarch64` в режиме TCG (без KVM для приложений) загружает небольшой initramfs, который получает rootfs через порт virtio-console в tmpfs. Работает значительно медленнее proot; объём RAM и количество ядер можно настроить.

Режим VM является необязательным при сборке (`with-vm` в workflow). Если он недоступен, экран настроек объяснит, чего не хватает, и покажет диагностическую информацию.

## Окно и внешний вид

- **Полноэкранный режим** или **плавающее окно** (требуется разрешение «Поверх других приложений»). Плавающее окно можно перемещать куда угодно (даже частично за пределы экрана), свободно изменять его размер (угол ◢), поворачивать (↻: 90°, долгое нажатие — 15°), закреплять (PIN фиксирует положение, размер и поворот, состояние сохраняется), делать прозрачным (ползунок ◐) и сворачивать (—). При сворачивании окно исчезает, а уведомление предлагает действия *Восстановить*, *Настройки* и *Выход*. Нажмите на терминал, чтобы открыть клавиатуру; нажмите за пределами окна, чтобы скрыть её. При повороте не на угол, кратный 90°, прозрачные углы всё равно перехватывают касания (ограничение Android).
- **Внешний вид** (применяется сразу, без перезапуска): цветовая схема (Dark, Solarized, Dracula, Nord, Gruvbox, Matrix, Light), размер шрифта и жирное начертание. Жест масштабирования двумя пальцами также меняет размер шрифта.

## Настройки (вкладки)

- **Окружение**: System / LiveCD, режим (VM является **экспериментальным**), объём RAM и количество ядер VM, режим окна, блокировка пробуждения (по умолчанию выключена), необязательный доступ к общему хранилищу (`/sdcard`, `~/storage/shared`; требуется разрешение Android, аналогичное `termux-setup-storage`, но запрашиваемое по необходимости).
- **Systems**: несколько систем одновременно; создание из встроенной Kyanite, импорт (tar, tar.gz, tar.xz, `.kya`), загрузка (последний релиз Kyanite, каталог Alpine, Ubuntu Base и Arch Linux ARM с проверкой контрольной суммы, если она опубликована upstream, либо любой URL с необязательной проверкой SHA-256), переименование, дублирование, удаление (при желании со случайной перезаписью), экспорт (tar.gz / tar.xz / `.kya`), создание снимков и восстановление.
- **Внешний вид**: 28 цветовых схем (в том числе вдохновлённых Vim), полностью настраиваемая палитра, размер шрифта и жирное начертание.
- **Безопасность**:
  - Блокировка PIN-кодом (+ тайм-аут повторной блокировки, + принудительный PIN, + блокировка после неправильных PIN-кодов).
  - Сжатие и шифрование AES-256-GCM **при хранении**: неиспользуемая система хранится в виде архива и распаковывается только на время активного сеанса. Ключ генерируется приложением (Android Keystore) или выводится из парольной фразы. Его можно переобернуть, сменить (с повторным шифрованием всех данных) или удалить в любой момент.
  - Конфиденциальность: запрет снимков экрана / скрытие из списка недавних приложений, скрытие содержимого уведомлений, блокировка буфера обмена, его очистка при выходе и завершение сеанса при выключении экрана.
  - **Запланированное уничтожение данных**: после N часов без открытия приложения, в заданную дату, после N неправильных PIN-кодов, при вводе принудительного PIN-кода или при включении USB-отладки. Сначала уничтожается ключ (криптографическое уничтожение), затем файлы перезаписываются данными CSPRNG, удаляются, а свободное место при желании заполняется случайными файлами (противодействие криминалистическому восстановлению). Проверка условий выполняется примерно каждые 30 минут.
- **Сеть**: главный переключатель. В выключенном состоянии локальный VPN без выхода блокирует весь трафик приложения и всех процессов внутри него, VM не получает сетевой интерфейс, а приложение не загружает файлы и не открывает браузер.
- **Обновления**: отключены / вручную (открывает страницу релизов) / автоматически (по умолчанию каждые 8 часов: проверка, загрузка и предложение установить обновление).

### Примечания о VM

Гостевая система загружает ядро Alpine `linux-virt` arm64 под QEMU TCG (программная эмуляция, без KVM), поскольку у Kyanite пока нет собственного ядра. На телефоне ожидание командной строки может занять примерно 10–40 секунд даже с небольшим rootfs, например Kyanite; передача самого rootfs занимает всего несколько секунд.

Если консоль зависает на сообщении `[kya]` на несколько минут, значит произошла ошибка. Аварийная оболочка или последнее сообщение покажут, на каком этапе возникла проблема.

Команда `exit` в оболочке гостевой системы (PID 1) выключает VM и завершает сеанс.

## Надёжность

Приложение никогда не закрывается самостоятельно. Если сеанс завершается (вы вводите `exit`, VM выключается или запуск завершается ошибкой), приложение остаётся открытым и показывает кнопки Перезапустить / Настройки. После неудачного или слишком короткого сеанса автоматический перезапуск не выполняется (никаких циклов сбоев).

Перед остановкой службы системы повторно упаковываются (сжимаются / шифруются), а распакованное дерево файлов помечается недействительным до удаления. Поэтому прерванное завершение работы не может оставить частично удалённую систему, которая всё ещё считается действительной. Если распакованное дерево осталось, оно будет повторно упаковано при следующем запуске.

## Важные ограничения

- proot не является границей безопасности (для изоляции используйте режим VM).
- Перезапись данных во флеш-памяти не гарантирует их физического уничтожения; надёжная гарантия — криптографическое уничтожение ключа.
- Android не разрешает бесшумную установку приложений: любое обновление требует вашего подтверждения и должно быть подписано тем же ключом.

## Build

Отправьте push в GitHub. `.github/actions/prepare-assets`:

1. Загружает proot (и QEMU) из apt-репозитория Termux с проверкой SHA-256.
2. Собирает ядро и initramfs для VM (`bash/build_vm_assets.py`) на основе Alpine `linux-virt` и `busybox-static` (`VM_KERNEL=debian` переключает на ядро Debian, `ALPINE_BRANCH` фиксирует ветку Alpine).
3. Получает rootfs Kyanite (`bash/fetch-rootfs.sh`): загружает релиз, проверяет SHA-256, проверяет подпись Ed25519 с помощью ключа, закреплённого в `bash/kyanite-release.pub`, и повторно сжимает архив с `xz -6`, чтобы приложение могло распаковать его с небольшим объёмом heap. Используйте параметр `kyanite-tag` action (или `KYANITE_TAG`), чтобы закрепить определённый релиз, например `v0.1.1`; по умолчанию используется последний релиз. Сборка завершается ошибкой, если у релиза нет действительной подписи (`KYANITE_ALLOW_UNSIGNED=1` отключает эту проверку).

Затем Gradle собирает APK. Контрольные суммы и URL загружаются как артефакт `provenance`.

Android 12 и более поздние версии могут завершать дочерние процессы («phantom process killer»); отключите эту функцию, если сеансы завершаются в фоновом режиме.
